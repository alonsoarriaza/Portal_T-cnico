1. Introducción al Proyecto y Arquitectura

1.1 ¿Qué es ABAXIAL PORTAL TÉCNICO?

ABAXIAL PORTAL TÉCNICO es una plataforma web empresarial diseñada para centralizar y optimizar la operativa diaria de servicios técnicos, gestión de clientes corporativos, inventario de hardware y software, archivo documental confidencial y planificación de intervenciones en cronograma.

1.2 Problema que Resuelve

Elimina la dispersión de información entre hojas de cálculo, sistemas desconectados y correos electrónicos. Permite que el equipo técnico y la dirección cuenten con una vista 360° en tiempo real de cada cliente, historial de equipos, incidencias y contratos de mantenimiento, garantizando además una trazabilidad auditada de cada acción realizada.

2.3 Paso a Paso para Iniciar la Aplicación

  1. Comprobar la Base de Datos en PostgreSQL: 
    # Crear la base de datos si no existe

  2. Compilar e Iniciar el Backend (Spring Boot): 
    cd backend
.\mvnw.cmd clean compile
.\mvnw.cmd spring-boot:run

  3. Instalar Dependencias e Iniciar el Frontend (React):

npm install
npm run dev -- --host
  4. Acceso desde el Navegador:
    • Local: http://localhost:5173
    • Red Local / IP: http://172.25.2.140:5173
    • Backend REST API: http://localhost:8080/api

4. Arquitectura Lógica y Capas de la Aplicación

4.1 Flujo Multicapa

[REACT UI] -> [API CLIENT] -> [SPRING SECURITY] -> [REST CONTROLLER] -> [SERVICE LAYER] -> [JPA REPOSITORY] -> [POSTGRESQL] | | v v [DTO Validation] [AUDITORIA SERVICE]

4.2 Responsabilidad de Cada Capa

  • Controladores (Controllers): Exponen endpoints REST, validan payloads con anotaciones Jakarta (`@Valid`, `@NotNull`) y aseguran el endpoint con anotaciones de autorización (`@PreAuthorize("hasAuthority(...)")`).
  • Servicios (Services): Contienen la lógica de negocio, validaciones complejas, cálculo de reglas transaccionales (`@Transactional`) y disparo de auditoría asíncrona.
  • Motor de Recurrencias (`RecurrenciaEngine`): Expande dinámicamente eventos periódicos (diarios, semanales, quincenales cada 14 días, mensuales y anuales) aplicando reglas de excepción individual y exclusión de fechas.
  • Repositorios (Repositories): Interfaces Spring Data JPA con consultas JPQL optimizadas y soporte para `JpaSpecificationExecutor`.
  • Entidades (Entities): Clases mapeadas con Hibernate/JPA con claves primarias identity, claves foráneas e índices de rendimiento.

5. Manual Funcional de Usuario

5.1 Módulo: Dashboard Principal

Ofrece una panorámica visual inmediata del estado de la empresa con contadores en tiempo real (clientes activos e inactivos, equipos, servicios, webs, eventos pendientes), accesos rápidos y lista de intervenciones inmediatas.

5.2 Módulo: Clientes (Ficha 360° y Altas/Bajas)

  • Crear Cliente: Asigna código único (`CLI-XXXX`), Razón Social, NIF/CIF validado, mantenimiento y ubicación.
  • Ficha 360°: Pestañas dedicadas para información, contactos, equipos, servicios, webs, documentos y cronograma.
  • Dar de Alta / Dar de Baja: Botones contextuales instantáneos en la cabecera del detalle y en cada fila del listado general. Al pasar a `ALTA`, el cliente se activa de inmediato; al pasar a `BAJA`, se archiva y se registra en auditoría.
  • Descarga de Ficha PDF: Genera al instante un PDF con toda la información técnica del cliente.

5.3 Módulo: Equipos (Cambio Rápido de Estado)

En el listado global de equipos, la columna Estado cuenta con un selector interactivo directo para usuarios con permiso. Permite alternar entre OPERATIVO, EN_REPARACION, BAJA o DESCONECTADO sin necesidad de entrar a la ficha del cliente, guardando inmediatamente y registrando el cambio en auditoría.

5.4 Módulo: Cronograma y Motor de Recurrencias Reales

Diferenciación Visual Profesional (Sin Emotes):
- Fijos / Recurrentes: Identificados en color morado corporativo e icono de repetición.
- Esporádicos / Recordatorios: Identificados en color verde claro corporativo.
- Solo para mí: Evento privado identificado con icono de candado.

Opciones de Recurrencia Disponibles

  • Diario: Se genera todos los días naturales.
  • Semanal: Permite seleccionar días específicos de la semana (ej: Lunes y Miércoles).
  • Quincenal: Salto exacto de cada 14 días exactos desde la fecha base.
  • Mensual: Día específico de cada mes con validación de meses cortos (ej: 15 de cada mes).
  • Anual: En la misma fecha cada año.
  • Límite: Sin fecha de fin (indefinido) o hasta una fecha de finalización configurada.

Gestión de Ocurrencias vs Serie Completa

Al hacer clic en una ocurrencia de una serie periódica, el usuario puede elegir:

  • Modificar solo este evento: Crea una excepción puntual para esa fecha sin alterar las demás semanas.
  • Modificar toda la serie: Actualiza las reglas globales de la serie.
  • Eliminar solo este evento: Excluye la fecha de la serie sin borrar el resto de ocurrencias.
  • Eliminar toda la serie: Da de baja la serie y todas sus apariciones futuras.

7.3 Consultas SQL de Utilidad para Ejecutar en el Query Tool

Para abrir la consola SQL, hacer clic derecho sobre la base de datos portal_abaxial y seleccionar Query Tool:

-- 1. Consultar todos los clientes ordenados por fecha de alta
SELECT id, codigo, nif_cif, nombre, estado, mantenimiento, activo, fecha_alta 
FROM clientes 
ORDER BY nombre ASC;

-- 2. Consultar equipos con su cliente asociado
SELECT e.id, e.codigo_inventario, e.tipo, e.marca, e.modelo, e.estado, c.nombre AS cliente
FROM equipos e
LEFT JOIN clientes c ON e.cliente_id = c.id
ORDER BY e.id DESC;

-- 3. Consultar eventos y recurrencias de calendario
SELECT id, titulo, tipo, recurrencia, dias_semana, visibilidad, fecha_inicio, fecha_fin_recurrencia
FROM eventos
WHERE activo = true;

-- 4. Consultar registro de auditoría en tiempo real
SELECT id, fecha, username, accion, entidad, detalles 
FROM auditorias 
ORDER BY fecha DESC 
LIMIT 25;

9. Flujo de Datos y Trazabilidad

9.1 Flujo Completo: Alta / Baja de Cliente

1. Usuario pulsa "Dar de alta" en el Frontend (React). 2. Axios emite: PATCH /api/clientes/5/alta con cabecera Authorization: Bearer . 3. JwtAuthenticationFilter intercepta la petición, valida la firma criptográfica y extrae el usuario ("admin"). 4. ClienteController verifica el permiso CLIENTE_EDITAR mediante Spring Security. 5. ClienteService.cambiarEstado(5, "ALTA", "admin") ejecuta: - cliente.setEstado("ALTA") - cliente.setActivo(true) - cliente.setFechaEliminacion(null) - clienteRepository.save(cliente) 6. AuditoriaService.registrarAsync("admin", "CLIENTE_ESTADO_MODIFICADO", "Cliente", 5, "Cliente ... BAJA -> ALTA"). 7. Respuesta HTTP 200 OK con el ClienteDetailDTO actualizado. 8. El estado de React se actualiza en tiempo real y muestra un Toast verde de confirmación.

10.2 Regla Crítica de Privacidad ("Solo para mí")

Aislamiento Estricto a Nivel de Base de Datos:
Cuando un usuario crea un evento con visibilidad = 'PRIVADO', el sistema aplica un filtro en la especificación JPA (`Specification`). Ni siquiera el Super Admin puede visualizar, listar, filtrar ni editar eventos privados creados por otro usuario. Si se intenta consultar el ID por API directa, el servidor responde 404 Not Found para no revelar la existencia del registro.

11. Sistema de Auditoría y Trazabilidad

El sistema de auditoría registra de forma inmutable y asíncrona (mediante @Async) todas las operaciones que alteran el estado de la información.

Acción Auditada Entidad Detalle Registrado
LOGIN Usuario Inicio de sesión exitoso con IP del cliente.
CLIENTE_ESTADO_MODIFICADO Cliente Transición de estado: `Cliente X (CLI-0001) — BAJA -> ALTA`.
EQUIPO_ESTADO_MODIFICADO Equipo Cambio de estado: `antes 'OPERATIVO' -> después 'EN_REPARACION'`.
EVENTO_CREADO Evento Evento agendado (ocultando título si es privado).
EVENTO_EXCEPCION_MODIFICADA Evento Modificación de una única fecha en una serie recurrente.
EVENTO_OCURRENCIA_ELIMINADA Evento Exclusión de una fecha específica de una serie.

12. Solución de Problemas Frecuentes (Troubleshooting)

Problema Posible Causa Solución Recomendada
Backend no arranca: Connection refused 5432 El servicio de PostgreSQL está detenido. Iniciar el servicio desde Windows Services (`services.msc`) o ejecutar `net start postgresql-x64-18`.
Error 401 Unauthorized / Token Expirado La sesión JWT ha superado el tiempo de expiración. Cerrar sesión e iniciar sesión nuevamente con las credenciales de administrador o técnico.
CORS Error al hacer peticiones API El origen del frontend no coincide con la lista permitida en backend. Comprobar `app.cors.allowed-origins` en `application.yml` y asegurarse de que incluye la IP/puerto actual.
Los clientes en BAJA no aparecen en la tabla Filtro de inactivos desactivado en la vista. Seleccionar en el desplegable de filtro de estado: "BAJA" o activar el checkbox "Incluir inactivos".
Un evento recurrente no aparece en un mes futuro La fecha de fin de recurrencia fue configurada en una fecha anterior. Editar la serie del evento y seleccionar "Sin fecha de finalización (indefinido)".

13. Mantenimiento, Backups y Buenas Prácticas

  • Copias de Seguridad Periódicas (Backups): 
    # Realizar dump completo de la base de datos
pg_dump -U postgres -d portal_abaxial -F c -b -v -f "backup_portal_abaxial.dump"

# Restaurar base de datos
pg_restore -U postgres -d portal_abaxial -v "backup_portal_abaxial.dump"
  • Evolución del Esquema con Flyway: No modificar manualmente tablas en producción con comandos DDL directos. Crear siempre un nuevo script de migración numerado en backend/src/main/resources/db/migration/V9__nombre_cambio.sql.
  • Almacenamiento de Archivos: La carpeta configurada en STORAGE_PATH almacena los ficheros binarios físicos organizados por cliente. Asegurar que dicha carpeta cuenta con permisos de lectura/escritura y se incluye en las políticas de backup del servidor.
